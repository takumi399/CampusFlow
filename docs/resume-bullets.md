# 简历写法

## 项目描述

**CampusFlow 青禾活动｜校园活动报名与候补系统**

基于 Spring Boot + MyBatis + MySQL + Vue3 的校园活动报名平台，支持学生报名、满员候补、自动递补、短时确认、二维码签到和管理员名单管理。

## 简历 Bullet

以下内容都能被当前代码和测试支撑：

- 基于 Spring Security + JWT 实现学生/管理员 RBAC，使用 BCrypt 存储密码，按角色限制管理端接口访问。
- 使用 MySQL 唯一索引、活动行锁和事务实现名额控制；在 20 个学生并发争抢 5 个名额的真实 MySQL 测试中，最终为 5 条确认报名和 15 条候补记录，未出现超卖。
- 设计候补 FIFO 自动递补与 10 分钟确认窗口，取消报名时在同一事务中完成状态变更、座位释放和下一名候补者的递补。
- 使用定时任务扫描过期递补，并在确认接口和扫描任务两侧加锁后重新校验截止时间，处理确认/超时竞态。
- 实现活动级 HMAC-SHA256 签到 token 和二维码签到，token 默认 5 分钟过期，签到接口同时校验登录身份、活动状态和报名状态，并保证重复签到幂等。
- 使用 EasyExcel 导出报名名单，提供管理员活动草稿、发布、结束、取消、手动签到和名单筛选功能。

## 面试时不要写的内容

不要写：

- 没有压测过的 QPS、TPS、响应时间。
- “支持百万用户”“高并发架构”这类与项目规模不符的描述。
- 没实现的 Redis、消息队列、微服务、分库分表。
- 没做过的线上稳定性指标或真实学校运营数据。

## 一分钟讲解顺序

1. 业务问题：活动名额有限，取消后候补要公平地自动递补。
2. 核心难点：同一活动并发报名、取消与递补同事务、递补确认超时。
3. 方案：活动行锁 `FOR UPDATE` + 唯一索引 + 状态机 + 定时扫描。
4. 边界：单体 MySQL 足够，当前不用 Redis。
5. 验证：5 个集成测试类、8 个测试用例覆盖并发、幂等、递补、签到和管理生命周期。
6. 取舍：结束活动保留报名历史；二维码提高伪造成本但不证明物理到场。

`Java 21`、`Spring Boot 3.5`、`MyBatis`、`MySQL 8`、`Spring Security`、`JWT`、`Flyway`、`Vue 3`、`Vite`、`Pinia`、`Element Plus`、`EasyExcel`、`JUnit 5`

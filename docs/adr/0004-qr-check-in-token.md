# ADR-0004：使用短时签到令牌生成二维码签到链接

- 状态：Accepted
- 日期：2026-11-08

## 背景

管理员需要在活动现场快速完成签到。直接展示活动 ID 或明文链接不安全，而在 MVP 中实现摄像头扫码识别会增加 HTTPS、相机权限和移动端兼容成本。

## 决策

- 管理员生成活动级签到令牌，令牌包含活动 ID、签发时间和过期时间。
- 令牌使用 HMAC-SHA256 签名，默认 5 分钟有效。
- 二维码内容是一个前端签到页面链接，学生用手机系统相机扫码打开。
- 学生必须在登录状态下签到，后端同时校验令牌和报名状态。
- 每个学生对同一个活动只能成功签到一次，重复签到返回已有结果。
- 不在 MVP 中实现前端调用摄像头识别二维码。

## 结果

优点：

- 生成二维码成本低，不需要摄像头权限。
- 令牌短时有效，不能通过修改活动 ID 伪造签到。
- 可以解释签名、过期校验和业务幂等。

代价：

- 令牌在有效期内可以被转发，无法证明学生一定在现场。
- 需要管理员现场展示二维码，签到仍依赖人工组织。
- 后续如果需要更强安全性，需要引入动态刷新、设备绑定或现场扫码设备。

## 备选方案

- 明文活动 ID：实现最简单，但可以被远程伪造，不适合作为简历项目的安全设计。
- 前端摄像头扫码：体验更完整，但需要 HTTPS、相机权限和跨浏览器兼容处理，MVP 性价比低。
- 每个学生独立一次性二维码：安全性更高，但需要额外的二维码分发和状态管理。

# ADR-0002：候补自动递补并设置确认截止时间

- 状态：Accepted
- 日期：2026-11-08

## 背景

活动名额释放后，候补队列需要继续推进。直接自动确认会让学生在没有准备的情况下被动占用名额；完全由管理员手动递补又会增加操作成本，也无法体现系统的自动一致性。

## 决策

采用“自动递补 + 限时确认”规则：

1. 确认报名取消后，按候补进入时间从早到晚选择第一名候补者。
2. 候补者状态变为 `PROMOTED`，获得一个 10 分钟的确认窗口。
3. 候补者在窗口内确认后变为 `CONFIRMED`，座位继续占用。
4. 超时未确认则变为 `EXPIRED`，系统继续递补下一位。
5. 如果队列为空，释放占位名额。
6. 递补、超时释放和确认操作都先锁活动行，再锁报名行，避免死锁。

## 结果

优点：

- 候补推进不需要管理员逐条操作。
- 状态机包含“待确认”和“过期”，能展示并发竞态和事务边界。
- 学生有明确的确认截止时间，业务规则可解释。

代价：

- 增加一个定时扫描任务。
- 增加 `PROMOTED`、`EXPIRED` 状态和确认截止时间字段。
- 需要处理“确认”和“超时释放”同时发生的竞态。
- MVP 只通过站内页面提示，不发送短信或邮件。

## 备选方案

- 自动确认：实现最简单，但用户体验差，且无法展示确认竞态。
- 管理员手动递补：实现简单，但自动化价值低。
- 使用延迟消息队列：更实时，但引入额外中间件，超出当前规模。
